# 엠플랜잇 장표 제작 규칙

실제 사내 PPT(페이퍼로지 + 화이트 배경 + 네이비/스카이)와 자사 제품 UI에서 뽑아낸 규칙이다.
AI가 만든 티가 나는 장표(검은 배경 + 네온 그라데이션 + 가짜 UI 목업 + 추상 카피)는 이 규칙 위반이다.

## 1. 산출물 형식

- 16:9 고정 슬라이드 `1280×720px`, HTML 1파일 + 이미지 `assets/`.
- 인쇄 CSS 필수: `@page{size:1280px 720px;margin:0}` + 슬라이드마다 `page-break-after`.
  → 브라우저 인쇄로 장표 1장 = PDF 1페이지.
- 키보드(←/→)·스크롤·하단 인디케이터 내비게이션.
- 기본 분량 5장 이내. 장당 메시지는 1개.

## 2. 브랜드 토큰

```
--navy:#1B468B   /* 로고 워드마크, 제목, 번호 배지 */
--sky:#399BC1    /* 로고 심볼, 키커, 강조선 */
--blue:#2563EB   /* 제품 UI CTA와 동일 계열 */
--ink:#0F1B2E  --tx:#334155  --tx2:#64748B  --tx3:#94A3B8
--bg:#FFFFFF  --bg2:#F5F8FC  --chip:#EAF1FC  --line:#E3EAF4
```

- 배경은 흰색/연회색. **다크 테마 금지.**
- 상단 5px 라인(navy→sky 그라데이션)이 모든 장표의 공통 시그니처.
- 서체: **페이퍼로지(Paperlogy)** 고정. `ai-solution/fonts/`에 4Regular · 7Bold · 8ExtraBold woff2(각 11,723자 전체) 동봉.
  ```css
  @font-face{font-family:"Paperlogy";font-weight:800;
    src:local("Paperlogy 8 ExtraBold"),local("페이퍼로지 8 ExtraBold"),
        url("fonts/Paperlogy-8ExtraBold.woff2") format("woff2")}
  ```
  ※ 루트 `index.html`에 박혀 있는 Paperlogy woff2는 **서브셋(292자)**이라 새 문구에서 글자가 깨진다. 재사용 금지.
  ※ PPT에서는 서체 이름을 `페이퍼로지 8 ExtraBold` / `페이퍼로지 4 Regular`로 지정한다(사내 PPT 테마와 동일).
- 로고: `assets/logo-mplanit.png` (PPT 원본에서 추출한 정식 로고).

## 3. 장표 구조(사내 PT 관습)

```
[상단] 키커(01 CREATIVE) · 제목 "제품명 — 한 줄 주장" · 부제 1줄 | 우측 서비스 URL 배지
[좌측 392px] 주요 특장점 01~04 (번호 배지 + 굵은 소제목 + 2줄 설명) + 칩 + 각주
[우측] 실제 제품 스크린샷 2~3장을 겹쳐 배치, 각 이미지 좌하단에 ①②③ 캡션
[하단] 제품명 · 페이지번호 (상단 경계선 1px)
```

- 특장점은 항상 **01~04 네 개**. 세 개면 허전하고 다섯 개면 글씨가 작아진다.
- **설명은 한 줄(30자 내외).** 두 줄로 넘어가면 문장을 자르지 말고 내용을 버린다.
  보조 설명·괄호 부연·"~까지" 같은 꼬리는 지운다. 판단에 필요한 명사만 남긴다.
- **표지에 블록 4개까지.** (헤드라인 / 한 줄 요약 / 흐름 / 솔루션 카드) + 하단 한 줄.
  시장 수치·출처·부연은 부록 장으로 내린다. 표지가 빽빽하면 아무것도 안 읽힌다.
- 우측 스크린샷 영역은 `742×470px`를 넘기지 않는다(넘기면 잘린다).

## 4. 이미지 규칙

- **가짜 UI 목업을 그리지 말고 실제 제품 스크린샷을 쓴다.** 사내 PPT(`ppt/media/`)에
  원본이 들어 있으면 거기서 추출한다.
- 추출 후 반드시 여백·검은 띠를 잘라내고 폭 1200px WebP(q82)로 저장한다.
- 예시 수치를 쓸 때는 캡션에 "예시"라고 적는다. 실제 진단·운영 데이터는 출처를 밝힌다.
- **광고주 데이터가 찍힌 화면은 마스킹 후 사용한다.** 광고주명·광고비·전환수·상품 URL은
  가우시안 블러 처리하고 캡션에 "마스킹 처리"를 명시한다. 메뉴 구조는 남겨도 된다.

## 4-1. 매체·채널 로고 규칙

- 애드보드(애드리포트)·커머스허브 설명에는 **연동 매체/채널 칩**을 반드시 노출한다.
  광고 매체 14(전부 칩으로): 네이버 검색 · GFA · NOSP · 카카오모먼트 · 카카오페이 · Google Ads · 메타 · 틱톡 ·
  크리테오 · 타불라 · Apple Ads · 당근 · 모비온 · 토스애즈
  판매 채널 7: 스마트스토어 · 쿠팡 · 카페24 · 11번가 · 토스쇼핑 · G마켓·옥션 · 톡스토어
- 공식 마크가 있는 매체(네이버 · 메타 · Google Ads · 틱톡 · Apple)는 `simple-icons` SVG를 쓰고,
  없는 매체는 **브랜드 컬러 점 + 매체명 텍스트 칩**으로 처리한다. 로고를 임의로 흉내 내지 않는다.
- 카카오처럼 저채도 워드마크는 작은 크기에서 안 읽히므로 텍스트 칩으로 대체한다.
- 표기는 연동 현황 안내 목적임을 각주에 한 줄 남긴다.

## 4-2. 핵심 문구(첨부 자료 원문) 사용

장표마다 사내 자료의 원문 한 줄을 인용 블록(좌측 네이비 바 + 연회색 배경)으로 넣는다.

| 장 | 문구 | 출처 |
|---|---|---|
| AI LAB 통합 | 판매와 광고를 한곳에서 — 광고비가 실제로 얼마를 팔았는지 확인 | 카카오쇼핑 API 연동 신청 자료 |
| Banner Fit | 한 번 입력으로 즉시 생성 | 솔루션 소개 PPT |
| Reels Studio | '만들기'가 아니라 '다듬기'부터 | 솔루션 소개 PPT |
| GEO | 고객은 AI에게 묻고 있는데, 우리 브랜드는 AI 답변에 등장하고 있나요? | AEO·GEO 개선 가이드 |
| GEO | 제로클릭 · 추천 누락 · 정보 왜곡 (3대 리스크) | AEO·GEO 개선 가이드 |

## 4-3. 솔루션 이미지맵

솔루션이 3개를 넘으면 **화면 썸네일 그리드 1장**(3열 × N행)을 따로 만든다.
타일 = 실제 화면 썸네일(object-fit: cover, 상단 정렬) + 단계 배지 + 제품명 + 한 줄 + URL/메뉴.
화면이 없는 솔루션은 빗금 플레이스홀더에 "화면 — 준비 중"으로 두고, 확보되면 교체한다.
이 장은 단독 배포(메일·메신저)용으로도 쓰이므로 다른 장 참조 없이 읽히게 쓴다.

## 4-4. 과장 방지 표기 기준 (필수)

제안 장표에는 마지막에 **부록 1장(근거·표기 기준)**을 붙이고, 아래 문장을 벗어나는 주장을 쓰지 않는다.

- 전체 구조도는 **서비스 포트폴리오** — 솔루션 간 자동 통합 아키텍처가 아니다
- GEO 점수는 **자체 진단 기준** — AI 답변 노출·인용률이나 검색순위가 아니다
- 화면 수치는 **캡처 시점 데이터** — 현재 성과가 아니며 광고주명·금액은 마스킹
- 채널·매체별 **연동 범위와 집계 주기가 다름** — 판매 매출과 광고 기여 성과는 구분
- 카카오쇼핑(톡스토어)은 **연동 승인 대기**
- MI 기능 범위·오픈 일정, 소상공인용 상품은 **확정 전**
- 광고주 프로젝트 수행 경험과 **AI 솔루션 도입 실적은 별개**
- 명칭 주의: 공식 홈페이지 Solution 페이지는 **M Ai Platform · MARS**로 소개.
  사내에서 쓰는 **MI** 명칭·네이버 자동입찰 설명은 공개 페이지에 없으므로 근거를 구분해 표기한다.

## 5. 문구 규칙

- **명사형으로 끊어 쓴다.** "…합니다" 서술형 설명 금지, 한 항목 2줄 이내.
  (예: ○ "입력 6단계 · 매체 규격 23종+ · 레이어 분리 · PSD" / ✗ "…를 지정할 수 있습니다")
- 제목은 **주장 + 근거**. "AI로 혁신합니다" 같은 문장은 쓰지 않는다.
- 제품 설명은 실제 화면의 메뉴·버튼·옵션 이름을 그대로 쓴다.
  (예: "라이트/에디터 모드", "짧게 2컷·기본 4컷·길게 7컷", "VEO 3.1 / Gemini Omni")
- 숫자를 쓸 때는 출처와 기준 시점을 함께 적는다. 시장 통계는 표지나 해당 장 하단에 출처 1줄.
- 영업 메시지는 마지막 장에 "도입 3단계 + 대상별 효용" 한 줄로 마감한다.

## 6. 작업 순서

1. 사내 PPT/PDF에서 최신 제품 화면·문구·수치를 먼저 추출한다(`unzip` + `ppt/slides/*.xml`, `ppt/media/*`).
2. 부족한 시장 근거만 웹에서 보강하고 출처를 적는다.
3. HTML 작성 → Chromium으로 장표마다 스크린샷을 찍어 **넘침·겹침을 눈으로 확인**한다.
   추가로 **넘침 자동 검사**를 돌린다(눈으로는 놓친다). 슬라이드는 `transform: scale`로 축소돼 있으니
   `배율 = slideRect.width / 1280`로 나눠 보정한 뒤, 요소의 `bottom > 718px`(슬라이드 밖)과
   `bottom > 푸터 top`(푸터 겹침)을 검사한다. 보정을 빼먹으면 전 요소가 오탐으로 잡힌다.
4. `page.pdf(width=1280px,height=720px,print_background=True)`로 PDF를 뽑아 함께 커밋한다.
5. PPT가 필요하면 `tools/build-pptx.js`(pptxgenjs)로 산출한다. 좌표는 **HTML px × 13.3333 / 1280 = inch**로
   그대로 환산하면 HTML 덱과 같은 화면이 나온다. 산출 후 `validate.py`와 슬라이드 경계 밖 도형 검사를 돌린다.
   (이 컨테이너의 LibreOffice는 변환이 되지 않아 PPT 렌더 QA는 불가 — 좌표 환산과 HTML 렌더로 대신한다.)
